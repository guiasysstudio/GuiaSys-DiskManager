# GDM-H03-01 — Correção das falhas de inicialização observadas no Windows

**Situação:** correções de engenharia aplicadas na branch de desenvolvimento; testes automatizados no GitHub Actions são evidência de build, **não substituem o novo teste visual em ambos os computadores**.

## Incidente reproduzido nos logs do usuário

O build `0.1.0` foi instalado em mais de um PC e exibiu dois tipos de erros. No log de 16/10/2026 (dados pessoais, seriais e chaves de licença não copiados para este documento):

- `application.unhandled / System.InvalidOperationException`: binding WPF `TwoWay`/`OneWayToSource` na propriedade calculada e somente leitura `MainViewModel.SelectedAllocatedPercent`.
- `application.unhandled / System.InvalidOperationException`: o mesmo problema em `MainViewModel.Progress`.
- `storage.inventory.failed / System.InvalidOperationException`: o inventário foi rejeitado com a exceção interna **`Identidade de disco ambígua.`**.

O log histórico de 08/10/2026 também mostrou erros de `SizeLabel` em colunas de tabela. Dados de 08/10 podem corresponder a uma compilação antiga e **não** são prova de que a operação ocorreu no build novo.

## Correções

### 1 — WPF de leitura sem TwoWay acidental

- `MainWindow.xaml`: `ProgressBar.Value` usa `Mode=OneWay` para `SelectedAllocatedPercent`, `SelectedPartition.UsagePercent` e `Progress`.
- A grade de partições é explicitamente **`IsReadOnly=True`** e `CanUserAddRows/CanUserDeleteRows=False`. As oito colunas usam `Mode=OneWay` (incluindo `SizeLabel`, `DisplayName` e propriedades calculadas). Os campos do editor de operações permanecem editáveis onde necessário.

### 2 — Identificadores de disco repetidos preservam leitura, nunca habilitam escrita

- A coleta de `Get-Disk` preserva as informações e geometria reais, mas agora identifica **grupos** de `UniqueId` não vazios que colidem entre números de disco diferentes, comparando sem diferenciar maiúsculas/minúsculas e ignorando espaços nas extremidades.
- Todo disco cujo identificador colidiu recebe `HasAmbiguousUniqueId=true` e `UniqueId=""` **somente na representação em memória**, com `HasStrongIdentity=false` e rótulo **“Identificador repetido — somente leitura”**.
- O mapa, inventário, volume e diagnóstico podem ser exibidos, **desde que a geometria e os demais campos obrigatórios sejam válidos**. Se os números de disco forem repetidos, houver partições sobrepostas ou campos inválidos, o inventário **ainda falha fechado**.
- O `SafetyService` rejeita qualquer mutação em discos sem identidade forte. O `StorageWriteGate.ReleasedAfterSafetyAudit` permanece `false` independentemente de licença; **nenhum disco é alterado por essas correções**.
- `storage.inventory.completed` agora registra **somente a contagem** de discos com IDs ambíguos, sem publicar serial/UniqueId nos logs.

### 3 — Testes sintéticos

`GdmH03InventoryIdentityTests`: colisões com diferentes caixas/espaçamento, IDs únicos, IDs faltantes, carregamento de JSON de inventário, bloqueio de operações em discos ambíguos, rejeição de números duplicados e geometria não confiável. Esses testes usam apenas objetos em memória; **não criam VHDX nem modificam discos físicos**.

## Teste de aceitação no VS Code local

Após a CI do commit final estar verde, execute na pasta local:

```powershell
git status
git pull --ff-only origin feat/full-disk-manager
dotnet restore .\GuiaSys.DiskManager.slnx
dotnet test .\GuiaSys.DiskManager.slnx -c Debug
dotnet build .\GuiaSys.DiskManager.slnx -c Debug
dotnet run --project .\src\GuiaSys.DiskManager\GuiaSys.DiskManager.csproj -c Debug
```

O programa inicia um novo processo WPF de testes, **sem reinstalar** a versão instalada. Avaliar se (1) abre sem avisos de binding; (2) apresenta discos e partições; (3) em discos com UniqueId repetido, mostra “somente leitura” sem possibilidade de execução; (4) o botão Aplicar permanece bloqueado por gate; (5) o status e o menu de licenciamento estão acessíveis. **Não clicar para aplicar operações físicas e não executar testes destrutivos.**

Se ainda falhar, enviar o **novo arquivo de log** de `%LOCALAPPDATA%\GuiaSys\DiskManager\Logs`, removendo previamente dados de licença/serial/pessoais. Analisar exclusivamente o erro reproduzido após a correção, sem inferir que todos os dispositivos do usuário são defeituosos.

## Limitações

Os dois sintomas documentados possuem correções de código, mas **a homologação visual e o inventário real ainda dependem de um novo teste humano**. O parser continua conservador e pode rejeitar outros casos de geometria ou metadados inconsistentes; não remover os gates para esconder erros. O lançamento comercial permanece **NO-GO** e `main` não foi modificada.
