# GDM-H03-02 — Mapa visual de todos os discos (referência MiniTool)

**Data:** 16/10/2026 · **Estado:** implementação WPF concluída em desenvolvimento; aceite visual e DPI em Windows ainda pendentes.

## Origem da solicitação

Na captura de 16/10, o GuiaSys Disk Manager já apresentava corretamente cinco discos físicos, nove partições, layout claro/azul e seleção de disco. O usuário mostrou também uma referência do MiniTool Partition Wizard: **cada disco ocupa uma linha com o número, GPT/MBR e tamanho à esquerda e suas partições em blocos lado a lado à direita**, com indicador de ocupação dentro dos volumes. O requisito é imitar essa organização funcional, **não** copiar recursos, logotipo ou ícones proprietários.

## Implementação

1. **Mapa multi-disco**: `DiskMapSection` contém `ItemsControl ItemsSource=DiskMapRows`. Cada linha exibe o disco, estilo GPT/MBR, capacidade, fabricante/modelo (quando Windows fornece), situação da identidade e extents da geometria real `StorageGeometry.Build`. Discos vazios aparecem como espaço não alocado.
2. **Largura responsiva proporcional**: `Controls/ProportionalPartitionPanel.cs` calcula larguras pela razão das extensões em bytes sobre a capacidade, alocando pequena área clicável até **38 px** a cada extensão para ESP/MSR/Recovery. O valor exato continua nos tooltips (não confundir o desenho aproximado com limites de execução). Toda a faixa ocupa a largura disponível e reage a resize/DPI sem canvas fixo.
3. **Título e ocupação**: os blocos distinguem `C:`, `D:`, tipo do Windows, sistema de arquivos e tamanho. Barra de ocupação de arquivos só fica visível quando `Get-Volume` forneceu contadores consistentes, sem criar porcentagem fictícia para EFI/MSR/RAW/não alocado.
4. **Seleção unificada**: clicar no cabeçalho de uma linha seleciona o disco; clicar em um bloco seleciona primeiro o disco proprietário e depois sua partição. Espaço não alocado seleciona apenas o disco — nunca inventa uma partição. A tabela, o mapa, os detalhes e as ações contextuais compartilham os mesmos objetos de modelo; nenhuma ação de clique executa comandos Windows.
5. **Segurança preservada**: conflitos de `UniqueId` seguem sem identidade forte e assinalados como *somente leitura*. Inventário inconsistente, sobreposições e partições fora do disco continuam falhando fechado. `StorageWriteGate.ReleasedAfterSafetyAudit=false` não foi alterado, tampouco o servidor GSL ou os mecanismos de atualização GitHub.
6. **Testes**: `AllDiskMapTests.cs` exercita múltiplos discos, unallocated, métricas válidas/desconhecidas, seleção, geometria inválida, layout proporcional, largura mínima e prevenção de expansão para centenas de partições. `tools/Test-DesktopUiContract.ps1` passou a exigir o mapa de todas as unidades, os bindings one-way de uso, comandos, segurança e ordem tabela → mapa → resumo.

## Homologação manual: Windows 10/11

Para testar sem instalar:

```powershell
git pull --ff-only origin feat/full-disk-manager
dotnet build .\GuiaSys.DiskManager.slnx -c Debug
dotnet test .\GuiaSys.DiskManager.slnx -c Debug
dotnet run --project .\src\GuiaSys.DiskManager\GuiaSys.DiskManager.csproj -c Debug
```

Verificar: todas as linhas (não apenas o disco selecionado); partições EFI, MSR, NTFS e Recovery no disco do Windows; disco MBR com NTFS; segmentos sem volume sem barra falsa; seleção de disco e partição; atualização F5; janela menor; DPI 100/125/150/200%; tooltips e foco no teclado. **Não clicar para executar operações físicas.** Enviar captura e log novo se houver erro. A assinatura, homologação comercial e executores físicos seguem **NO-GO**.

## Limites

Barra com áreas mínimas amplia visualmente partições pequenas. Nem o fundo colorido nem os indicadores de uso são medição do espaço *não alocado* ou prova de segurança do sistema de arquivos. O modelo de dados preserva offsets/tamanhos para diagnósticos; nenhum botão altera geometria. O MiniTool é **referência de usabilidade**, não dependência externa ou código copiado.

## Ajuste H03-03 — legibilidade das partições pequenas

A captura posterior do usuário comprovou o problema: partições MSR/EFI/Recovery apareciam como **`N...`, `M...`** e seus tamanhos eram cortados porque o painel lhes dava apenas **38 pixels**. Comparado ao MiniTool, faltava separar visualmente **tipo e tamanho** em duas linhas.

- Cada extensão agora recebe pelo menos **100 unidades de layout WPF**, com título compacto como **`(FAT32)`, `(MSR)`, `(Recup.)`, `C:(NTFS)`, `Não alocado`**, e tamanho em linha separada **`209,72 MB`, `16,78 MB`, `478,96 GB`**, conforme valores reais retornados pelo inventário.
- O cálculo visual ainda atribui espaço proporcional adicional às extensões maiores, mas **não comprime os rótulos pequenos**: se o total mínimo exceder a largura disponível, a linha apresenta **rolagem horizontal independente**, preservando o cabeçalho do disco.
- O novo painel usa a largura visível do ScrollViewer em tempo de execução, inclusive ao redimensionar a janela ou alterar DPI. As partições sem dados de ocupação continuam sem barra de progresso fictícia.
- Fundo de partições mais claro com texto escuro; o mapa continua **exclusivamente de consulta**, e os tooltips preservam offset e tamanho exato.
- Regressões cobertas por `AllDiskMapTests` e `Test-DesktopUiContract.ps1`. **Teste visual humano em Windows permanece necessário**.

Nenhuma operação em disco, chave de licença ou atualização remota foi alterada nesta etapa.
